## Who is watching

A committee with mixed backgrounds: some experts in the field, some not, often tired after many projects. They decide in the first 15 seconds whether to pay attention. They score against a rubric that usually covers: problem significance, technical approach/innovation, execution/results, presentation clarity, and impact. They will ask questions afterwards, so the video must never claim more than the team can defend.

Write so that a non-expert follows the story and an expert finds the details correct.

## Structures by video type

Times are for a 2:50 pitch; scale proportionally.

### Expo pitch (2–3 min): problem → idea → how → proof → plan/impact

| Beat | Share | Content |
|---|---|---|
| Hook | 8–10 % | A concrete stake or scenario, not the project name. "Encrypted traffic recorded today…" |
| Context / standard / need | 8–10 % | Why now: deadline, standard, statistic |
| Problem with current approach | 8 % | Make the gap visible |
| Reveal | 6–8 % | The project name and one-line idea, built from a visual metaphor |
| How it works | 30–35 % | Follow one real input through the real system; then the hero mechanism up close |
| Proof | 12–15 % | Measured results, or targets/budgets clearly labelled |
| Plan / roadmap | 8–10 % | (in-progress projects) concrete next milestones |
| Impact + end card | 8–10 % | Applications, then team, supervisors, institution, partner logos |

### Booth loop (60–90 s, muted-first)
One concept explained through a tiny story, two fixed "stations" (e.g. device and server), every key object labelled, captions always on, last frame = first frame. No reliance on the voice for meaning.

### Demo video (3–6 min)
Problem (20 s) → solution overview with architecture (40 s) → live demo of the core flow with real footage and zoom callouts (50 % of the time) → results against baseline → limitations and future work → credits. Real footage is the proof; graphics explain what the footage can't show.

### Presentation video (6–15 min)
A narrated version of the defence: chapters with title cards, one diagram per idea, results with charts, and a recap slide at the end. Keep a visible chapter indicator so viewers can navigate.

### Teaser (30–60 s)
Hook, reveal, one hero visual, one result, name. Music-led, very little text.

## Writing the script

- **Pace:** 140–150 words per minute for a calm AI or student narrator. A 2:50 pitch is about 380–410 words. Leave 5–10 % slack under the hard cap.
- **One idea per sentence.** Sentences around 8–18 words. Read each aloud mentally: if you'd need a breath mid-sentence, split it.
- **Say numbers the way people say them** in the voice script ("a hundred and eleven cycles"), and write them normally in captions ("111 cycles").
- **Concrete before abstract.** Follow one real input (a packet, an image, a sensor reading) rather than describing the system in general.
- **Verbs that match the ledger status:** "achieves / measured" only for measured; "targets / projects / is budgeted for" for estimates; "will / plans to" for planned work.
- **Drop throat-clearing** ("In this video we will…", "As we all know…").
- **End on the name and the institution,** not on "thank you".
- **Two voices of text:** the caption version (correct spelling, punctuation) and the voice version (spelled for pronunciation, pause tags). Keep both in sync in `video-design.md`.

## Applause moments

Plan 3–5 visual payoffs where an abstract idea becomes obvious in a single image. These are what judges remember. Patterns that work:
- **Merge / unify:** two separate things slide together into the project's mark or one block.
- **Reconfigure:** the same hardware or structure visibly switches modes (a datapath splitting into lanes).
- **Pack / fill:** a container filling with exactly the right number of items (a memory word holding 4 values, then 2).
- **Tamper fails:** one byte, pixel or parameter changes and the system visibly rejects it.
- **Before → after:** the same scenario with and without the project, side by side or as a wipe.
- **Counter lands on the number:** a cycle counter or metric counts up and stops exactly on the spoken figure.
- **Pull back reveal:** the camera zooms out from one detail to show the whole system.

Each payoff gets sound (a click, tick or soft chime) and a 0.5–1.5 s hold.

## Review rubric

Score the storyboard and script 1–5 on each line as a sceptical judge from outside the field. Revise anything under 4. Repeat at least twice.

| Criterion | 5 looks like |
|---|---|
| Hook | First 10 s create a concrete stake without jargon |
| Clarity | A non-expert can retell the idea in one sentence afterwards |
| Technical depth | An expert sees the real architecture and real names, with no hand-waving |
| Evidence | Every number is on the ledger with the right status wording |
| Visual storytelling | Each scene shows (not tells) its idea; 3+ applause moments |
| Pacing | 140–150 wpm, holds after payoffs, nothing rushed, under the cap with slack |
| Identity | Looks like this project's poster/brand, not a template |
| Rubric fit | Every official criterion is hit explicitly at least once |
| Accessibility | Captions, readable sizes, works muted (mandatory for loops) |
| Ending | Name, team, supervisors, institution and partners, all correct |
